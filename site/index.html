Why

Most harnesses give you a loop and leave the hard parts to you.

A context that grows until it dies, a trace you can't replay, a "done" you can't trust. Anchor ships the hard parts.

01 — Verification

Evidence, never vibes

Every tool result lands on AgentResult.evidence. run_tests stamps the tree hash it ran against, and latestEvidenceForTree ties a green run to the exact bytes. The engine carries evidence — what to gate on it is your policy, not a hidden wall.

02 — Durability

Durable by construction

Conversation, workspace, and the agent's own notes survive folds, restarts, and budget deaths. The SDK ships the resumption primitives — thread store, checkpoints, phase pauses, revival planning — so resuming is wiring, not research.

03 — Machines

Sandbox-first

The machine is part of the design, not an afterthought: one provider contract, three shipped adapters, and an executable conformance suite that holds every adapter to its promises.

Out of the box

The parts every agent needs, already wired.

Agent loop with dials

Budgets (steps / tokens / USD), repeated-call detection, silent-tool advisories — guardrails on by default, each with an off switch. Phases describe the approach, never a second gated engine.

Streaming by default

One wire path: every model call streams. Text and reasoning deltas, tool calls, compaction, checkpoints, and finishes all arrive as typed events.

Durable memory

ThreadStore carries the conversation across runs; compaction is derived from the model's real context window; reasoning is journaled but never re-sent.

Notes & spill storage

A reserved .anchor/notes.md (git-excluded, checkpoint-carried) is the agent's memory across folds; oversized tool output spills to sandbox files and stays addressable instead of vanishing.

Revival

A dying run leaves a handoff (request_revival); planRevival + ThreadBudget fund the next run — same task, phase, and budget — and when the caps are spent, a human gets the note, quoting the agent's own words on what remains.

Snapshots & resume

A pluggable snapshot hook (git-backed by default, push optional), phase-boundary pauses, heartbeats and cross-process cancel polling owned by the engine.

Traces you can replay

One fanout: one sequence number, redaction applied before every sink — NDJSON file, database rows, and a live projector share the same ordering.

Sandbox plugins

One SandboxProvider contract: Heyo microVMs, Docker, local. Capabilities are promises — the conformance suite holds adapters to them. Store-backed sessions give adopt-and-fallback continuity for free.

Typed handoffs

finish({ handoff }) is shaped by your JSON schema; the engine declares the parameter, carries the object, and never interprets it.

Priced & windowed models

llmFromCatalog reads live prices and the genuine context window from the provider catalog — budgets and compaction configure themselves correctly.

Quickstart

Ten lines to a working agent.

chat.mjs
import { chatAgent, llmFromCatalog, runAgent } from "anchor-ai-sdk";

const { llm } = await llmFromCatalog({
  baseUrl: "https://openrouter.ai/api/v1",
  apiKey: process.env.OPENROUTER_KEY,
  model: "z-ai/glm-5.3",
});

const result = await runAgent(
  { task: "Explain what this repository does" },
  { llm, agent: chatAgent },
);
console.log(result.summary);
repo-triage.mjs — give it a machine
import { codingAgent, runAgent } from "anchor-ai-sdk";
import { docker } from "anchor-ai-sdk/sandbox/docker";

const sandbox = docker().create({
  repoUrl: "https://github.com/you/your-repo",
  ref: "main",
});
await sandbox.start();
try {
  const result = await runAgent(
    { task: "Run the tests and fix the failing case" },
    { llm, agent: codingAgent, sandbox },
  );
  console.log(result.summary, result.checkpointRef);
} finally {
  await sandbox.destroy();
}

Runnable versions live in examples/ — including a non-coding agent with its own strategy and tool, no sandbox.
